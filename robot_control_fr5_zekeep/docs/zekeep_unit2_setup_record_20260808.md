# ZKBOT-301ED 2호기 PC 제어 실측 세팅 기록

작성일: 2026-08-08  
대상: ZKBOT-301ED 2호기  
범위: USB-시리얼 통신, 원점복귀, HMI 조그 비트 실측, 3축 PC 단일축 이동 검증

> 이 문서는 1호기 값을 복사하지 않고 2호기에서 실제 HMI 조작과 PC 피드백으로 확인한 결과를 기록한다. 다운로드 원본 키트는 수정하지 않았고, 2호기 전용 사본만 사용한다.

## 1. 최종 상태

- PLC 통신: 정상 (`D8001 = 24320`, 반복 점검 `10/10`)
- 통신 오류: 오늘의 정상 검증 구간에서 체크섬 오류 및 무응답 `0`
- 비상정지: `X5 OFF`
- 리밋: `X0/X1/X2 OFF`
- 모드: 수동 (`D90 = 1`, `M201 ON`)
- 원점: A1/A2/A3 모두 실제 `0.00°`로 수렴
- 크리프 속도: `D76 = 200`
- 펌프/밸브: OFF
- PC 단일축 이동: A1/A2/A3 각각 실동작 확인

## 2. 전용 제어 폴더와 포트

- 원본 키트: `/home/yr/Downloads/zkbot_pc_kit`
- **2호기 전용 사본**: `/home/yr/SimFirst/zkbot2_control`
- 2호기 전용 설정: `zkbot2_config.py`
- 자세 저장 파일: `data/poses.json` (1호기와 공유 금지)

현재 2호기 어댑터는 다음 USB 물리 경로로 고정했다.

```text
/dev/serial/by-path/pci-0000:00:14.0-usb-0:7:1.0-port0
```

`/dev/ttyUSB0` 같은 번호는 USB 재삽입 순서에 따라 바뀔 수 있다. 위 경로는 **현재 꽂힌 USB 물리 포트 기준**이다. PC 다른 USB 구멍으로 옮기거나 1·2호기를 같이 연결한 뒤에는 아래 명령으로 반드시 다시 확인한다.

```bash
ls -l /dev/serial/by-path /dev/ttyUSB*
```

## 3. 통신 사양

| 항목 | 확정값 |
|---|---|
| USB 어댑터 | CH340 (`1a86:7523`) |
| 배선 | USB-시리얼 ↔ DB9 |
| 시리얼 | 9600 bps, 7E1 |
| PLC 프로토콜 | Mitsubishi FX Programming Protocol Format 1 |
| Modbus 사용 여부 | 사용하지 않음 |
| 링크 확인 | ENQ → ACK, `D8001 = 24320` |

`zk_scan.py`는 Modbus-RTU 스캐너이므로 이미 FX 프로토콜이 확인된 2호기 일상 운용에는 사용하지 않는다.

## 4. 2호기 HMI 조그 비트 실측

`zk_hmi_diff.py`를 읽기 전용으로 실행한 뒤, HMI에서 각 축의 양/음수 조그를 약 1~2초씩 눌러 PLC M비트 변화를 기록했다.

| 축 | 양수/원점 방향 | 음수 방향 | 확인 방법 |
|---|---|---|---|
| A1 | `M1 + M31 + M101` | `M2 + M103` | HMI 캡처 |
| A2 | `M3 + M41 + M105` | `M4 + M107` | HMI 캡처 |
| A3 | `M5 + M51 + M109` | `M6 + M111` | HMI 캡처 |

### 1호기와의 차이

1호기 문서에 있던 A1/A2/A3의 `M181/M183/M185` 보조 비트는 2호기 HMI 캡처에서 나타나지 않았다. 2호기 전용 `zk_pose.py`, `zk_escape_limit.py`에는 위 표의 값만 반영했다. **1호기 스크립트나 비트를 2호기에 그대로 사용하지 않는다.**

## 5. D76 및 원점복귀

### 초기 상태

첫 읽기 전용 점검에서 `D76 = 0`이었다. D76은 FX의 비유지 영역이라 전원 재투입 후 0이 될 수 있으며, 0이면 원점복귀가 리밋을 만난 뒤 크리프 속도 없이 덜컥거리거나 완료하지 못할 수 있다.

표준 기동으로 `D76 = 200` 복구를 확인했다.

### 발견 및 수정한 원점복귀 조기완료 문제

원본 `zk_home_run.py`는 과거 원점복귀 이력 플래그(`M121/M122/M123`)가 이미 ON인 상황에서, 각도가 `±1°` 이내면 너무 이르게 M120을 해제할 수 있었다. 실제로 A2 `-1.92°`, A3 `-0.89°`, A2 리밋 `X1 ON` 상태를 정상 원점처럼 보이는 문제가 발생했다.

2호기 전용 스크립트는 다음 조건을 모두 만족할 때만 완료 처리하도록 수정했다.

- M120을 최소 4초 유지
- A1/A2/A3 각각 `±0.3°` 이내
- `X0/X1/X2` 모두 OFF
- 원점 플래그 A1/A2/A3 ON

또한 `zk_startup.py`도 원점 플래그만 보지 않고 실제 각도와 리밋을 함께 확인한다. `--check` 모드는 펌프·밸브가 ON이어도 더 이상 출력 OFF 명령을 내리지 않는다.

### 실제 리밋 탈출 기록

조기완료 후 A2 `X1 ON` 상태에서 `zk_escape_limit.py A2`를 실행했다.

- 사용 비트: `M4 + M107`
- 펄스: 0.3초 1회
- 각도: `-1.92° → -4.35°`
- 결과: `X1 OFF`, 조그 비트 잔류 없음

그 뒤 보강된 원점복귀를 수행해 최종적으로 3축 `0.00°`, 모든 리밋 OFF를 확인했다.

## 6. PC 단일축 목표각 이동 실증

2호기 전용 `zk_pose.py`에 아래 명령을 추가했다.

```bash
python3 zk_pose.py goto-axis <A1|A2|A3> <목표각도> [--tol 0.5]
```

이 명령은 원점 플래그, 통신 품질, 비상정지, 소프트리밋을 확인하고 확인된 축의 조그 비트를 사용한다. 이동 중에도 관절 피드백을 읽으며 목표 근처에서 조그 비트를 해제한다.

| 시험 | 명령 | 실측 결과 | 목표 오차 | 육안 확인 |
|---|---|---:|---:|---|
| A1 | `goto-axis A1 -5` | `-4.961°` | `0.039°` | 확인 완료 |
| A2 | `goto-axis A2 -5` | `-4.961°` | `0.039°` | 확인 완료 |
| A3 | `goto-axis A3 -5` | `-4.995°` | `0.005°` | 확인 완료 |
| A3 재시연 | `goto-axis A3 -5` | `-4.967°` | `0.033°` | 확인 완료 |

A3를 `-5° → 0°`로 단일축 이동한 한 번의 시험은 감속 여유 때문에 `-0.89°`에서 멈춰 `±0.5°` 목표오차를 만족하지 못했다. 이 결과를 성공으로 처리하지 않았고, 표준 원점복귀로 정확히 재동기화했다. 이후 `goto-axis`에는 저속 접근 뒤 2% 미세 접근 단계를 추가했다. 이 개선된 양수 방향 정밀도는 다음 사용 전에 별도로 재검증한다.

## 7. 현재 사용하는 스크립트

모든 명령은 다음 폴더에서 실행한다.

```bash
cd /home/yr/SimFirst/zkbot2_control
```

### 읽기 전용 상태 점검

```bash
python3 zk_startup.py --check
python3 zk_stall_diag.py
python3 zk_pose.py show
```

### 전원 투입 후 표준 기동

```bash
python3 zk_startup.py
```

이 명령은 필요할 경우 D76을 200으로 복구하고, 실제 각도가 원점이 아니면 원점복귀를 수행한다. 이동 전에는 작업공간, 비상정지, 리밋 상태를 확인해야 한다.

### 단일축 시험

```bash
python3 zk_pose.py goto-axis A1 -5 --tol 0.5
python3 zk_pose.py goto-axis A2 -5 --tol 0.5
python3 zk_pose.py goto-axis A3 -5 --tol 0.5
```

### 리밋이 ON인 경우

원점복귀를 바로 반복하지 않는다. 해당 축을 먼저 리밋에서 벗어난 뒤 다시 원점복귀한다.

```bash
python3 zk_escape_limit.py A2
python3 zk_home_run.py
```

`zk_seek_limit.py`는 리밋 위치가 불명확할 때 사용하는 복구 도구다. 실제 팔 위치를 눈으로 확인하고, 충분한 작업공간을 확보한 상태에서만 사용한다.

## 8. 안전 규칙

1. HMI/PC/ROS 노드 등 **한 프로세스만** 같은 시리얼 포트를 열어야 한다.
2. PC 조그는 레벨 방식이다. 강제 ON만 하고 OFF를 누락하면 축이 계속 움직일 수 있다. 전용 스크립트의 `finally` 해제를 우회하지 않는다.
3. 전원을 끄면 팔이 처져 카운터와 실제 위치가 달라질 수 있다. 다음 기동 전에는 `zk_startup.py --check`부터 실행한다.
4. 원점 플래그만으로 현재 위치를 판단하지 않는다. 실제 각도와 리밋 상태를 같이 본다.
5. 리밋이 ON이면 원점복귀를 바로 반복하지 않는다. `zk_escape_limit.py`로 먼저 탈출한다.
6. 1호기와 2호기를 동시에 연결할 때 `/dev/ttyUSB0/1` 번호를 신뢰하지 않는다. `/dev/serial/by-path/`를 재확인한다.
7. 두 로봇의 작업공간이 겹치면 상위 인터록 없이 동시 이동하지 않는다.

## 10. 오늘 적용한 파일 변경

- `zkbot2_config.py`: 2호기 전용 USB 물리 포트와 데이터 경로
- `zkfx.py`: 환경변수 기반 기본 포트 지원
- `zk_pose.py`: 2호기 실측 3축 비트, 별도 poses 파일, 단일축 시험 명령
- `zk_home_run.py`: 원점복귀 조기완료 방지 조건
- `zk_startup.py`: 실제 각도·리밋 기반 준비 판정, 완전 읽기 전용 `--check`, 2호기 포트 전달
- `zk_escape_limit.py`: 2호기 포트와 실측 비트 적용
- `zk_stall_diag.py`, `zk_hmi_diff.py`, `zk_seek_limit.py`, `zk_shutdown.py`, `zk_status.py`: 2호기 전용 경로 또는 포트 적용
