# 06. 프로젝트 범위

## 팀 전체 시스템

| 파트 | 담당 | 이 파트와의 접점 |
|---|---|---|
| Voice AI · Server · FMS (유예린) | STT · LLM · TTS, Job 생성, 12단계 공정 오케스트레이션, DB | `ExecuteTask` / `CellControl` / `/cell/status` 계약 |
| AI Vision · 품질검사 (김성엽) | YOLO 입고 검사 · 조립 결과 검사 | 조립 완료 후 검사는 서버가 호출 — 이 파트는 검사 결과를 받지 않음 |
| Unity · TurtleBot (김영호) | 관제 GUI · 디지털 트윈, 팔레트 운반 · 지게차 | `/fr5/joint_states`, 글로벌캠 UDP, 셀 상태 표시 |
| **Robot Cell (김애리)** | FR5 · ZeKeep 로봇셀 전체 | — |

## 이 파트가 하는 것

- 서버 인터페이스 계약(ROS 2 Action / Service / Topic) 설계 · 구현, 일시정지 · 재개 · 오류코드
- 셀 오케스트레이터 — task → phase 시퀀스, 상태기계, 모의/실물 어댑터
- FR5 벽 삽입 파이프라인 — 밑판 측정 · 랙 파지 · 운반 · 정렬 · 하강 · 안착 · 출하
- 자체 비전 보정 계통 — 카메라 4대, 색점 · ArUco · 뎁스, 자코비안 실측, 기준 관리(집 타입별)
- FR5 브리지 — 명령 단일 창구, 동결 복구, 안전 봉인
- ZeKeep 3축 PLC 제어 — MODBUS-RTU 직결, 역기구학, 원점 · 흡착 · 반송
- 운영 콘솔 — 조그 · 기록/재생 · 관절 트윈 · 카메라 감시
- 글로벌캠 중계 — 비전팀 factory_view 스택 기동 · 콘솔 중계

## 이 파트가 하지 않는 것

- YOLO 기반 자재 · 품질 검사 (비전 파트) — 이 파트의 색점 검출은 로봇 보정 전용이며 검사와 무관
- 생산 Job 생성 · 공정 순서 판단 · DB (서버 파트) — 이 파트는 받은 task 하나를 실행하고 결과만 보고
- Unity 화면 · 디지털 트윈 렌더링 (관제 파트) — 이 파트는 관절각과 영상만 발행
- TurtleBot 자재 운반 (관제 파트)

## 경계에서 정한 규칙

| 규칙 | 이유 |
|---|---|
| 하강 시작은 사람이 버튼으로 확인 | 힘 센서가 없어 접촉 감지가 카메라 의존 — 안전상 1회 개입은 의도한 설계 |
| 실패 후 부품을 랙에 되돌리는 건 사람 | 어긋난 부품을 로봇이 되돌리면 2차 사고 |
| 검출 실패를 로봇 이동으로 풀지 않는다 | 탐색 이동이 관측자세를 밀어내 기준을 틀어뜨린 실측(0.8~0.9 mm) |
| 게이트는 완화하지 않는다 | 완화 3건이 모두 더 큰 손상으로 이어진 전례 |
| 자동 복구는 되돌릴 수 있는 것만 | 노출 탐색 · 관측 재중심 · 기준 자리 폴백 — 로봇 자세를 바꾸는 복구는 하지 않음 |

## 한계와 남은 일

- 서버 `ExecuteTask` 와 벽 삽입 파이프라인(`house_cycle`)을 잇는 어댑터와 `part_code/slot → 벽 색` 매핑 테이블이 없음
- 서버 즉시 정지 경로 미구현 (`immediate_pause_enabled=False`) — 사이클 도중 정지는 콘솔 abort 만 가능
- 안착 자동 판정이 전 색에 되지 않음 — 벽이 여러 장 꽂히면 기둥 색점이 가려짐
- 자코비안은 관측자세 1점의 국소 선형화 — 자세가 늘어나면 정식 핸드아이 캘리브레이션이 적합
- 힘 센서 없는 접촉 판정은 기둥이 먼저 부러지는 경우를 못 잡음 — 정공법은 F/T 센서 또는 RCC
- 로봇과 작업대가 한 몸이 아님 — 하나만 밀려도 기준이 틀어짐
