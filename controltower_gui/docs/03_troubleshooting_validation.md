# 문제 해결과 검증 범위

## 확인한 현상

| 항목 | 관찰 / 현재 구현 | 남은 확인 |
| --- | --- | --- |
| 로봇팔 자세 | 실제 관절값을 Unity에 반영 | 작업 전 구간과 초기 기준 재검증 |
| FR5 자재 결합 | 그리퍼가 자재 위치에 와도 결합하지 않은 사례 | 그리퍼 입력, 예정 자재, 베이스 상태와 결합 조건 추적 |
| FR5 그리퍼 | 개방률 비례 표시와 별도 임계값 판정 | 실제 중간 폭 파지와 결합 이벤트를 분리 검증 |
| 터틀봇 위치 | 실제 HOME 정렬 후에도 Unity와 위치 차이 발생 | odometry 누적 오차·좌표 변환·홈 보정 반영 확인 |
| 영상 | 검사 상태와 UDP 영상 경로가 별도 | 각 스트림 송신/수신과 프레임 재조립 확인 |

자재 밀집이나 바퀴 slip을 단일 원인으로 확정하지 않았습니다. 벽이 없으면 SLAM·Nav2를 사용할 수 없다는 의미도 아닙니다. 이번 포크리프트 구현은 고정 odometry 경로와 ArUco 도킹을 사용합니다.

바퀴 slip은 센서 고장이나 네트워크 전송 실패와 구분합니다. 회전량 기반 odometry에서는 바퀴가 헛돌거나 미끄러지면 실제 이동량과 추정 이동량이 달라질 수 있습니다. Unity에 그 추정 좌표가 그대로 전달되면 모델 위치도 실제와 어긋납니다. 이번 HOME 정렬 후 불일치에는 좌표 기준과 정렬 결과 반영도 함께 점검해야 합니다.

Unity에서 Pi로 직접 연결하는 수동주행은 사용자 현장 테스트에서 성공했습니다. 모든 장애·재접속 조건을 검증했다는 의미는 아닙니다. 조작 방법은 [README](../README.md#unity에서-터틀봇-수동주행)에 정리했습니다.

## 최신 거리 무관 보정

잡기 신호 처리 시 다음 벽을 현재 위치와 관계없이 그리퍼에 결합하고, 놓기 신호 처리 시 해당 설치 Socket으로 보정하도록 변경했습니다. 자재 순서와 중복 결합 방지는 유지합니다. 이는 위치 불일치를 보완하는 표현 로직이며 실제 파지 성공 확인을 대체하지 않습니다.

2026-09-15 원본 프로젝트의 Assembly-CSharp.csproj를 `dotnet build --no-restore`로 확인한 결과 오류 0개, 경고 19개였습니다. 새로 복사한 경로에서 Unity 최초 임포트 및 실제 로봇 Play 실행은 아직 검증하지 않았습니다.

## 다음 실연동 점검

### 오프라인 검증 완료 항목 (2026-09-16 정리)

- Unity 엔진에서 접촉 박스 관련 검사 42개 통과, 실패 0개: 형상이 있는 자재 12개, FR5 마운트 2개와 포크리프트 접촉 박스 정렬을 확인했습니다. 형상이 없는 자리표시용 오브젝트 27개는 검사 대상에서 제외했습니다.
- 그리퍼 개방률 0·30·80·100%에서 부착점 유지, 반복 정렬 시 위치 유지, 벽 부착 후 10cm 상승 추종과 분리를 확인했습니다.
- 이전 서버 수신 진단 로그의 FR5 관절값 101건과 ZeKeep 관절값 1건을 메시지 처리 코드에 재생했습니다. 102건 모두 파싱·이벤트 전달에 성공했으며, 물리 시뮬레이션 중 FR5 접촉 박스 정렬 검사에서 실패가 없었습니다.
- 재생 데이터는 간격을 두고 저장된 관절 진단값입니다. 전체 WebSocket 원문·시간 간격·시퀀스와 그리퍼·생산 공정 기록이 없어, 실제 파지 신호부터 전체 조립 완료까지의 재현 검증을 의미하지 않습니다.

정렬 도구는 `Tools > ModularHouse > Align Contact Boxes To Geometry`에 있습니다. 형상 기준으로 접촉 박스를 계산하며, 팔레트에 실린 다른 자재는 팔레트 자체 범위에 포함하지 않습니다. 완성 주택은 조립된 자재를 포함한 범위를 사용합니다.

### 실제 서버·로봇 연결 시 확인 항목

1. 로봇 ID, joint_names, radians 단위를 확인합니다.
2. 실제 파지 전후의 grip/current_operation 수신값과 손가락 모델 연결을 확인합니다.
3. 예정 자재 ID, 베이스 배치 상태, 현재 결합 자재를 확인합니다.
4. 위치가 어긋나도 잡기 신호 시 예정 벽이 붙고 놓기 신호 시 올바른 Socket에 설치되는지 확인합니다.
5. 중복 상태 메시지, 처음부터 닫힌 상태, 재접속을 시험합니다.
6. HOME 정렬 전후 실제 위치와 Unity 위치·방향을 비교합니다.

장기 개선안은 대상 자재 ID와 파지·설치 완료 이벤트를 명시적으로 전달하고, 홈 정렬 완료 시 Unity의 기준 변환을 갱신하는 것입니다. 이 개선안 전체가 구현 완료된 것은 아닙니다.
